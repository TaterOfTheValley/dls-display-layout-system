Design thesis

Profiles first. Hardware second.

Proposed

The first cut should change this computer's Windows display arrangement reliably. Monitor input switching is a separate hardware concern and stays explicit until the setup proves it needs integration.

02 · Interaction design

A tray popover built for the two-second decision

The app should stay out of the way. A tiny popover exposes the current computer, the active profile, the display footprint, and the next action. The same actions are available from global shortcuts.

A

Visible ownership

Show each display as a labeled tile. “Left / center / right” is the user's physical mental model; Windows' numeric IDs are implementation detail.

B

Safe repetition

Applying an already-active profile is harmless and idempotent. The hotkey can be used without first checking the tray state.

C

Recovery without drama

If a monitor identity is missing, keep the current arrangement, show the missing display, and offer re-detection rather than guessing.

Interaction boundary: the first version changes the Windows desktop arrangement. It does not pretend that enabling a display also changes the monitor's physical input source.

03 · Configuration UI

A compact editor for the moments between switches

The switcher stays tiny during daily use; profile setup gets a dedicated, polished editor. It should feel like a small control panel, not another Windows Settings maze.

04 · System shape

Local control, stable monitor identities

The utility runs on each computer whose Windows layout must change. Profiles are local and explicit. A future shared controller can coordinate them, but it is not required to make the core handoff useful.

Recovery
